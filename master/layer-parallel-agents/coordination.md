## 多端多 agent 协调

### 角色

- **根协调角色**：维护跨端 req doc 和消息路由，不写端代码，不替端内 agent 出实施 spec。
- **各端 agent**：端内代码、端内 spec / ADR 和自决实施；边界以各端 AGENTS 为准。
- **Owner**：定需求、审跨端产品选择、参加联调并处理高风险闸；不当人工通讯员。

### 6+1 流程

1. **起需求**：跨端需求由根协调角色落 req doc；单端上下文明确时由该端直接起。
2. **取活**：端标签对应的 open issue 就是待干任务。
3. **细化**：端 agent 落端内 spec，自检后在需求 issue 宣布进入实施。
4. **开发**：从 `origin/{{default_branch}}` 开任务分支；实施、变化、证据写 issue；PR 按 `Refs` / `Closes` 收口并接受新眼睛 review。
5. **联调**：单端问题回该端；跨端 mismatch 在 issue 评论确定改哪一端或契约。
6. **收口**：状态、验证、风险和残项回到 issue / PR，不把完成状态手抄进多份 doc。
- **+1 回改 req doc**：只有重大偏离才更新正文，并保留为什么改的证据。

### 消息总线与隔离

- doc 写正文，issue 写状态与跨端变化，PR 写交付验证；三者不能互相替代。
- 每个端只改自己的范围；识别到跨端扩散时，自己写评论、附技术草案并报告，不把上交做成 owner 代办。
- 每个端使用独立 worktree；物理布局和反转条件见 `docs/project/worktree-isolation.md`。
- 中间 PR 使用 `Refs`，最终验收满足才 `Closes`，避免误关仍承担消息总线的需求 issue。
