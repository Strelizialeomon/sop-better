## 1. 选活 + 这次验什么

exp-015 把「多调研」压成候选,最大反方是"它免费涌现、再上闸=过度治理"。owner 决定:不把"多调研"另立成 §1 硬闸,而是**并进一个更有结构论证的机制**——**spec 派独立新眼睛**(§1.3 现只把新眼睛用在代码 diff,最载重的 spec 进生产只过 owner 收口、无独立眼)。「多调研」当这只眼的**第一条检查项**搭车进 SOP,**少一半仪式**。

验证问题(便宜验证):**这只 spec-eye 是"省事"(逮真问题)还是"添堵"(对好 spec 瞎咬)?** —— 真跑三炮,一份固定 brief(三查:① 实证+信源 ② 验收可机检 ③ 范围/形态/边界;且"没问题的维度直说无显著问题、别凑数")。

爆炸半径:零(全只读 · 合成 spec 在 scratchpad、真 spec 只读 media-ops 不写)。

## 2. 三炮 + 结果

| spec | 来源 | 高危 findings | 总评 | 表现 |
|---|---|---|---|---|
| 坏 spec | 合成(我埋 3 坑:数据量拍脑袋 / 验收口号 / 导 PII 无鉴权) | **3,全真** | 不能交付 | 3 坑全中,还白捡 CSV 编码(BOM/手机号科学计数)等专家细节 |

**真 spec 那炮(最有分量)**:这是 media-ops 自己 SOP 调教出的**好 spec**(决策来源 / linchpin + 信心 / 做不做范围 / 可机检验收都到位)。新眼睛:
- **逮到我读时唯一挑出的拍脑袋**——"远端 MySQL = 只改 config host、无需改连接代码"(F1.1):远端 ≠ 本地,TLS/超时/连接池在高延迟下都不在"改 host"那步,要真连一个远端实测。**这正是「多调研」检查项在真料上打响。**
- **挖出我没看全的真隐患**:① F3.1(**高**)——真账号 PII 数据上一个"可能裸公网"的远端库,只靠一句口头纪律兜、**无可观测卡点** → 建议升硬闸(TLS 已开 / 非 0.0.0.0 / 备份已验,PR 逐项打钩);② F1.2(中)子表"都能经 account_id 派生"是断言没核实,Notification/HotItem 万一全局表 → v1.1 漏隔离串户;③ F3.3(中)"单 owner 多端同连"是 v0.1 明确支持的形态,但多端并发写冲突被"不做冲突解决"(那是 v1.1 多运营的事)带过了。
- **会分辨**:维度 2 判"无显著问题、基本达标",好的地方不硬挑;严重度分得准(1 高=真安全洞、其余中低);还诚实标"未翻代码,findings 是待核实假设"。

## 3. 判读:这次**两关都过了**(对照 exp-015 的「多调研」单飞)

- **设计缺陷(可证、不靠 N)**:§1.3 把"新眼睛"只用在**代码 diff**,而"跳 writing-plans"下**最载重的产物是 spec**;真 spec 上那个**高危安全洞 owner 收口没逮、独立眼 60 秒逮到**——演示出来的结构漏,不是一个数据点。
- **代价不对称**:一只 ~60 秒 subagent vs(a)照"远端=改 host"拍错返工 /(b)真账号数据上裸库一次不可逆泄露。
- **过度治理这关(头号)实测被压住**:好 spec 0 高危 + 真 spec"无显著问题"维度直说——机制**会分辨、不是 false-positive 机器**;再加"琐碎 spec 免"carve-out 兜底。

→ 按 lab 先例(exp-007/008/009:**单个真事故 + 过两关 → 即改 STANDARD**,跨项目复验另记"待补"),够格落地。

## 4. 反方 / 诚实 caveats(对自己结果也上反驳)

1. **才 1 个真项目**(media-ops),没到 exp-004 的 2/2 跨项目;合成那两炮是我编的料、坑我埋的,弱一档。
