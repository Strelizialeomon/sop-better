## 1. 病灶:旧文本不是"漏了中间地带",是**明令禁止**那种停

初判以为 §1.9 只是缺一档。**reviewer A 挖出更准的形态**:旧「永不阻塞」的原句是

> 只在这几种停:违反已冻结契约 / 严重偏离目标 / 改跨端骨架 / 越界他人 scope。

「**只**」字使它成为一条**排他闭包**——不在这 4 项里就**不许停**。所以 owner 描述的第 3 种情况("撞死了,停下来喊人")在旧文本下是**违规**的,不是没定义。

于是 agent 撞上"技术上自己解不了、又不跨端不改需求"的东西时,旧文本只留下两条路,**两条都是坑**:

| 走法 | 后果 | 本仓实证 |
|---|---|---|
| 凭"永不阻塞"硬猜着往下堆 | 脑补上游 | geo-reverse #2(`issue-pr-workflow.md:103` 记着:开发凭"永不阻塞"自己把需求补了) |
| 静默趴窝、等人来问 | 回到 exp-049 治的病 | owner 本次的触发场景 |

**这次改动的真正内容 = 把"停"从违规变成合规,并给它上纪律。** 不是补一个空白格,是打开一个闭包。这也是出题税那笔账能证成的理由:**旧文本构造上装不下这件事,删不出等价物**。

## 2. 改法

### 2.1 三档表(STANDARD §1.9)

判据**不用 owner 原话里的"挡不挡后续"**——reviewer B 指出那个轴在最贵的场景里是循环的:准确评估"挡不挡"的前提是已理解影响面,而你之所以卡住正因为不理解它。换成写下一行代码时就能自查的代理判据:

> **接下来要写的每一块,需不需要对这个卡点的答案做假设?**

## 3. 新眼睛 review(按家规常设授权直接派,未回头问 owner)

两个独立子代理并行:**A = 护栏核对**(exp-006 / exp-047 镜头)、**B = 对抗挑刺**。两份**都判"要改了再合"**,findings 已全部处置。

### A 的核对结论

- 原 escalate bullet 的 7 条限定(触发无条件 / 动作 / 收件人分流 / owner 当面交办也走 / 做不做归 owner / 送达归 agent / 草案只到 how)+ 原永不阻塞的 2 条(触发 / 动作)**逐条在位**。
- **反例场景专验通过**:"识别出要改 req doc,但这件事自己完全能做"(命中原 escalate 闸、不涉及"解决不了")——改后仍够得着,没被三档表的前提吞掉。三层渲染(base / parallel / multiend)也各自保留独立 escalate 条目。
- **修了一处旧漏洞**:STANDARD 的收件人分流原本缺 fallback「否则给 owner」,渲染层(`parallel-agents.md` / `sop-init`)早有——本次补齐,方向是渲染层回灌真相源。
- 稀释一处(已知代价):「**只**在这几种停」的排他限定删除。补偿控制 = 可证伪门槛 + 豁免 + 硬停清单前移。

### B 攻破的 / 没攻破的

- **攻破**:F1 豁免缺失、F2 门槛是计数、F3 两个"停"混淆、F4 判断轴循环 + tie-break 论证错、F5 行为面查法假阳假阴、F6 子代理责任放错边、F7 三条重叠的轴。**全部采纳**(处置见 §2)。
- **没攻破**:子代理读不读得到这条(B 本人即证据——本仓 `CLAUDE.md` 全文注入子代理 system prompt);与 §1.2 新眼睛闸(exp-050)不打架("子代理不可用 → 停在闸前"正是第 3 档的实例);与「不假民主」「≠ 替别人补缺」无硬冲突。

### B 的 F6 改变了一处设计方向(值得单记)

初稿把"列卡点"的责任压在**子代理**身上。B 指出责任在**派单方**:子代理的报告形态由 prompt 决定,而且**下游没人接**——规则只说子代理要列,没说收到卡点的 agent 要干什么,升级链中间那一跳是空的。改成:**派子代理时把「卡点(没有写『无』)」写进 prompt 的输出格式,收到报告的 agent 负责过一遍本表**。这是"结构挡住 > 加规则",正对北极星。
