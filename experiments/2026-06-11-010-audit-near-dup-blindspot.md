## 1. 现象

- exp-009 §6 立过一条预测:"传播靠现成机制 —— 项目的 collaboration doc 若缺这条 carve-out = `/sop-audit`「模板版本差」(exp-007)自动逮的漂移 → 回灌。"
- owner 真在 taoxi-geo 跑了 `/sop-audit`。报告查出 2 条模板漂移(消费侧验链接、决策闸收口),**唯独没报 exp-009 的 escalate carve-out**——正是这次要回灌的那条。**预测被证伪。**

## 2. 根因:近似 ≠ 覆盖,被「防过度报」护栏挡住

- taoxi-geo `collaboration.md` 其实**已有** §1.9 不假民主的本地近似版(§10 红线 `:635`「SOP 没定 → 走 escalate flow,不在 scope 窗口让 owner pick」+ `:643`「跨端 feat → escalate coord」)——覆盖了"escalate 别做成 pick"的**大原则**。
- 模板版本差 check 自带一条**防过度报**护栏(`SKILL.md:28` 末:"⚠️ 比的是缺了该有的新护栏、**不是逐字一致**,别把合理差异报成漂移")。project 有近似版 → 这条护栏把它判成"已覆盖、合理本地偏离、无漂移" → **静默放过**。这是个**讲得通的判断**,不是 audit 瞎了。
- 但 exp-009 carve-out 是为一个**具体 failure mode** 加的:owner **当面亲口**交办扩范围/跨端 → 别吞、别把 escalate 做回 pick。taoxi-geo 的近似版把问题框成"SOP 定没定",**缺的正是"owner 当面交办"这个触发角度**(grep `当面/老板亲口/做不做` 零命中)——而 #206 事故恰恰栽这。**"近似版缺要命那一刀" ≠ 合理本地偏离,是真漂移**,却被防过度报护栏豁免了。
- **同形 meta**:这是 audit **自己**版的 exp-004/007/008/009 —— 最强护栏(防 cry wolf 的"别把合理差异报成漂移")指向了**错误动作**(放过真缺口)。审查工具忠实执行了"防过度报",不是违反。

## 3. 关键判断

### 为什么"一次"就改(顶 §3.5「复发 2+ 次才改规矩」,过两关)

- **设计缺陷**(非数据点):模板版本差 check 的"有/无"粒度 + "别报合理差异"护栏,**构造上**装不下"项目有近似版、缺关键 delta"这一类 —— 可证地把真漂移误判成合理偏离。不靠 N 成立。
- **代价不对称**:**回灌纪律**(exp-007)整条都压在"audit 能逮到模板漂移"这个假设上;这个盲区让**每次靠 audit 的回灌都可能静默漏掉近似版的 delta**。修 = SKILL 净增 ~1 句;复发 = 回灌机制对"近似版漂移"系统性失灵。

### 怎么修才不变成 cry wolf(关键张力)

- **不能**改成"近似版一律逐刀比、全报"—— 那会把 audit **自己**变成它最该治的过度治理(每个近似条款都报 delta = 噪音洪水,直接破坏头号"防过度治理"职责)。
- **靠语义、不靠字面标记**:让 audit **逐条语义比**——看 template 那条有没有针对某个**具体场景 / 边界的限定**(carve-out、反例、"即使 X 也要 Y"式例外),项目近似版只搬大原则、漏了那个限定 = 仍 `missing` + **强制标信心**;普通措辞 / 详略差异照旧宽放。LLM 本就会语义读,这是它现成能力、不新增负担。低噪音、正打盲区。
- **(新眼睛补回 · 见 §4)**:首版押的是"带 `carve-out` / exp-NNN 标记的条款才较真",被新眼睛一 grep 打穿——`exp-NNN` 在 templates/ **零命中**、`carve-out` 9 个模板只 2 个带,连这次该逮的"验链接"护栏(`issue-pr-workflow.md:45`)都不带任何标记。**字面标记信号在自己的 template 里就不成立** → 改判据为"语义上有没有具体限定",不依赖谁记得标字。

### 诚实标注(比 exp-009 还要小心)

- 这是**单点** dogfood(taoxi-geo 1 例),且改的是 **audit 自己** —— over-flag(把正当本地偏离也报成 delta)的风险真实存在。所以 SKILL 那一句**收窄 + 强制标信心**,并在此明记:**若复用中发现它开始为合理偏离凑数报 delta,回炉收更窄或撤。** 不靠它一锤定音,只靠它"别再静默放过 carve-out 级的 delta"。

## 4. 修复(本次 · sop-better 母本)

- **`skills/sop-audit/SKILL.md`** 模板版本差 check:加一句「**近似 ≠ 覆盖**」收窄护栏 —— **逐条语义比**:看 template 那条有没有针对某具体场景 / 边界的限定(carve-out / 反例 / "即使 X 也要 Y"式例外),项目近似版只搬大原则、漏了那个限定 = 仍 `missing` + **标信心**;普通措辞 / 详略差异照旧按"合理本地偏离"宽放(不破防过度治理)。
- **不动** `STANDARD §1.9`(escalate carve-out 本身没错,exp-009 已落)、**不动** templates(漂移在 audit 的**查法**、不在被查的护栏)。
- **过 exp-005 自审**:无新章节 / 新品牌概念(并进现有「模板版本差」bullet);SKILL 净增 ≤10(实测 1 句);不重抄 STANDARD。
- **新眼睛复核**(§1.3 · 同 exp-006/009 形态 · **逮到真 bug**):首版把判据押在"`carve-out` / exp-NNN 字面标记"上,新眼睛 grep 实证该信号在 templates/ 不成立(`exp-NNN` 零命中、`carve-out` 9 选 2、连"验链接"护栏都没标)→ 会**假阳性安全感**:看着收窄了盲区,实则只盖碰巧带字的少数条款。据此把判据从"字面标记"改成"**语义上有没有具体限定**"(template 刻意把事故号留 PLAYBOOK、正文干净 → 任何字面锚点都靠不住,只能靠语义)。**这正是本 exp 主张的方法论(真跑 / 多眼睛 > 单脑自证)用在自己身上一次。**
