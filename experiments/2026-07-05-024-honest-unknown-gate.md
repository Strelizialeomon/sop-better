# exp-024 · 诚实无知闸

- **日期**:2026-07-05
- **真实任务**:用户要求把“知之为知之,不知为不知”写成 SOP 铁律,并明确补充互联网调研同等重要。
- **本次撒手档位**:L3(改 STANDARD / 母本 / sop-audit / PLAYBOOK,影响后续项目生成与审计)

---

## 1. 选活 + 定档

这是 owner 对 agent 行为的底层要求:缺关键信息、用户前提可能错、外部事实不确定时,agent 不能为了顺着任务继续往下编。可以打断任务,也必须说清不知道什么。

现有 SOP 已有反驳协议、三层引导、方案前调研包、缺上游反弹不自补,但缺一个更上位的“诚实无知”总闸。用户还给出八荣八耻,希望它变成规则记忆钩子,不是一句口号。

爆炸半径:

- 写太轻:只变成“不要瞎猜 / 不懂就问”,agent 仍会用训练记忆或业务臆想找补。
- 写太重:所有小事都联网 / 确认,拖慢低风险局部补丁,违背右尺寸。
- 写歪:重复创造一套联网调研协议,和 exp-021 的方案前调研包打架。

## 4. AI 跑完,我来评

- **AI 做了哪些决策**(它替我想的部分):
  - 把规则命名为“诚实无知闸”,定位为现有反驳 / 三层引导 / 方案前调研包 / 反弹不自补的上位总闸。
  - 把查询路径拆成本地事实和外部事实,明确外部事实要联网查可靠来源。
  - 把八荣八耻逐条映射到已有规则,防止新增平行体系。
  - 把 audit 查法扩成“口号缺触发条件和动作”。
- **超出我预期 / 我自己想不到的地方**:
  - 新眼睛先审 spec,指出“八荣八耻还像装饰”和“验收只搜词不够硬”,促成映射表和组合 `rg` 验收。
  - 这条不是替代方案前调研包,而是规定“任何时候不知道都不能装知道”。
- **翻车 / 我得纠偏的地方**:
  - 首版描述偏本地事实,用户补充互联网调研同等重要后才补上外部事实路径。
