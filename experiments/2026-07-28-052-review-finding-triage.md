## 1. 病灶:不是"漏了分类",是**收口判据在数学上不可达**

初判以为缺一张分类表。真实形态更硬——旧文本两处写死复审收口:

| 位置 | 旧文本 |
|---|---|
| `STANDARD §1.2` | **口径**:findings 是待核实假设,交作者 / owner 解 |
| `issue-pr-workflow.md` 第 3 步 | 验收全过 + **findings 清零或显式标记** |

findings 的**生成者是 reviewer,而 SOP 从没限制它拿什么当尺子**。叠上 `§1.10 主动建议 / 补盲区`(明确授权 agent 主动提最佳实践、补盲区),于是每一轮复审 reviewer 都**合法地**能当场立一条新标准、生出一批新 findings。

**所以 `findings 清零` 不是一个会到达的状态,是一条移动的地平线。** owner 审到第五六轮不是标准高,是这个判据没有不动点。而另一条出口 `或显式标记` 是**没有定义的万能口**,两种用法都坏:

| 走法 | 后果 | 本次实证 |
|---|---|---|
| 不敢用"显式标记",继续审 | reviewer 每轮新立标准 → **审到自己加需求**(业界名 gold plating:加需求的人是干活的自己,不是甲方) | owner 本次的触发场景 |
| 烂用"显式标记" | 真违约也被标记糊过去,`code review 必留` 这道承重墙**空转** | 未观测,但结构上敞着 |

与 exp-051 同形:那次是「永不阻塞」写成**排他闭包**、装不下"正确地停";这次是「findings 清零」写成**不可达判据**、装不下"审完了"。**都不是漏一格,是构造上没有出口。** 这也是出题税那笔账能证成的理由——旧文本删不出等价物。

## 2. 改法:两档,不是四档

### 2.1 为什么砍到两档(owner 的 `keep it simple` 当场生效)

首版设计是四档(违约 / 缺口 / 健康债 / 出题)+ 三轮上限 + 逐轮严格递减。用 `§5.1 过度治理是头号查` 的镜头审自己的提案,砍掉两块:

| 砍掉 | 为什么砍 |
|---|---|
| **②③④ 三档合并成一档** | 那三档的差别是**重不重要**,而这是 owner 的优先级判断、不是 reviewer 的。让 reviewer 分档 = 又还给它一个自由度。reviewer 只需要一刀:**指得回一条已存在的东西吗?** |
| **三轮上限 + 逐轮递减** | 是防"① 档也无限"的计数兜底。但**已存在的验收是有限集,① 天然有上界——收敛是结构保证的**,再加计数闸就是拿仪式补结构(§5.1 正是这么判的) |

### 2.2 落定的规则

> **复审只能引用标准,不许当场立新标准。**
> ① 指得回一条**已存在的**验收 / 契约 / doc / 原本能跑的行为 → 本轮必修(① 是**待核实的引用、不是判决**:被审方举证引错 / 不适用 → 降 ② 或撤回,争不下归 owner · 本句由新眼睛逼出,见 §4.1);
> ② 指不回去(含 reviewer 当场想到的"更好做法")→ **本轮一律不修**,按 §1.9 escalate 上交,做不做归 owner。
> **收口 = 本轮 ① 归零**(② 不阻断收口)。

### 2.3 两道 owner 原话里没有、不写就失效的闸

| 闸 | 为什么必须有 |
|---|---|
| **窄豁免**:安全 / 数据损坏 / 崩溃 / 明确回归四类免验收背书直判 ① | 真实项目验收写得糙是常态,"并发下丢数据"常引不回任何明文验收。不留口子会**漏真问题**;但口子必须**窄且可枚举**——exp-051 的教训:门槛一宽就成万能借口 |
| **引用必填写进子代理 prompt 输出格式** | 本仓 review 由独立子代理执行(§1.2 + exp-050),它**只吃 prompt**。不写进输出格式,两档就只是纸面装饰。同形先例:§1.9「把『卡点(没有就写"无")』写进 prompt 的输出格式」 |

### 2.4 刻意接受的代价(不是没看见)

窄豁免盖不住"逻辑确实错、又不崩不丢数据"那一类——它落 ②,要多一次上报往返才能升成本轮必修。**这是刻意取舍:宁可多一次一句话往返,也不要一个能自我扩权的 reviewer。**

## 3. 调研依据(按 §1.4 信源分档标注 · 一手 / 二手分开列)

## 5. 抽一条教训 → 回填 PLAYBOOK

**收口判据的生成者不受限,判据就没有不动点。** 凡是"把 X 清零"型的完成条件,先问一句:**X 的生成者是谁,它凭什么停?** 生成者能合法无限造 X(reviewer 可当场立标准、检查者可当场提高标准),这条判据就必然长成"审到没完"或"拿万能标记糊过去"。修法不是加轮次上限(拿仪式补结构),是**把生成器的输入锁成有限集**——收敛就自动成立。

→ 已写入 `PLAYBOOK.md`?**[ ] 暂不回填**——首版写进去了,被新眼睛按 PLAYBOOK:7 准入规矩(「没跑过实验、没有数据的,不准进来」)判 ① 后撤回。本轮唯一的数据是 owner 报的**病灶侧**症状(审了五六轮 + 自己加需求),不是**疗效侧**证据(两档判据真的让复审收敛了)。与 exp-048 / 049 / 050 / 051 同一纪律(见 exp-051:116),**一起等真项目实跑后集中回填**。
