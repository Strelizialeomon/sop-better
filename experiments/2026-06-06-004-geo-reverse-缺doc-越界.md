# exp-004 · 真用 geo-reverse 暴露洞:缺 req doc 时开发 agent 越界自补

- **日期**:2026-06-06
- **真实任务**:geo-reverse 业务方提了 issue #2,但**只提了 issue、没把关联的 req doc 推到远端**(`docs/superpowers/specs/2026-06-06-ai命中判定闭环-design.md` 在远端不存在)。观察开发 agent 拿到 issue 后的反应。
- **本次撒手档位**:N/A —— 这不是一次"主动撒手实验",是**真用 SOP 时撞出的洞**(同 exp-002 §5 的发现方式:真跑 > dry-run)。

---

## 1. 现象

- issue #2 顶部写"关联需求 doc:<链接>",链接指的文件**从没被建/推过** → 悬空链接。
- 开发 agent(戴开发帽)发现 doc 缺失,**凭「永不阻塞 + 主动补盲区」自己动手把需求 doc 写了**。
- owner(开发帽)当场拦下:"需求文档不该开发写,应该 issue 评论让业务方补 doc 上来——请检查是不是 SOP 没写明白。"

## 2. 根因(三层洞,洞 3 是主因)

1. **生产侧没顺序闸**:SOP 只说"issue 链接到 doc",没说"doc 先 push 到远端、issue 再指过去"。提 issue 与推 doc 是两个独立动作,没东西保证顺序 / 原子 → 悬空链接;且 issue 指了会悬空的相对路径,没指稳定引用。
2. **消费侧没前置校验**:SOP 让开发"把 doc 变成 spec",默认 doc 在;缺"起手先验链接解析得开"。
3. **(主因)「自决 / 永不阻塞」缺角色边界**:§1.9「spec 没 cover 的边界 → 自决」+ §1.10「主动补盲区」,没有 carve-out 说明"别的角色该给而缺的交付物 ≠ 你能自决的边界"。**agent 没违反 SOP,是忠实执行了一条没有边界的最强原则** → 被 SOP 自己推着越界。

> 自愈来源:这次 doc 最终是业务侧(haihai)13:46 commit `e418079` 补推上远端的——**靠的是人工拦截,不是 SOP**。SOP 当时帮倒忙。

## 3. 关键判断:为什么"一次"就改 STANDARD(顶 §3.5 "复发 2+ 次才改规矩")

- §3.5 那条铁律是给**调参类**踩坑设的(某阈值 / 数字错一次别急改)。这次不是调参错,是**一条无边界规则主动把 agent 导向角色越权**——属**设计缺陷**,不是数据点。
- 代价不对称:修 = 一句 carve-out;复发 = agent 伪造需求 / 污染真相源(正是 §1.8 最怕的"会说谎的凭据")。便宜的修 vs 昂贵的复发 → 现在修,但**保持最小**,不借机加重流程。
- owner 拍板:go。

## 4. 修复(本次)

- **STANDARD §1.9**:加角色边界 carve-out(永不阻塞 ≠ 替别人补缺的交付物;缺 / 悬空 = 坏交接 → 反弹不自补)。
- **STANDARD §1.8**:凭据保真做成**双向**(生产先落 doc 再开 issue·指稳定引用 / 消费起手先验链接;悬空链接 = 会说谎的凭据)。
- **STANDARD §5 + `skills/sop-audit/SKILL.md` §4**:新增 finding「凭据失真 / 交接断裂」(悬空链接 / 缺交接闸 / 约束块缺 carve-out)。
- **templates**:`agent-constraints.md`(标准块)、`issue-pr-workflow.md`(开 issue 顺序 + 接 issue 验链接)、`collaboration.md`(业务起需求顺序 + dev 接需求验链接 + 永不阻塞 carve-out)同步落地,使生成的项目 CLAUDE.md 真带上。

## 5. 抽一条教训 → 回填 PLAYBOOK

撒手给开发 agent 时,**上游缺交付物**这一类边界必须显式 carve-out——否则 agent 会把"永不阻塞 / 补盲区"误读成"替别人把缺的需求 doc 写了"(越界伪造)。凭据保真要**双向**:不只"别让你的 issue 说谎",还要"行动前验别人给的凭据没说谎"。
