## 1. 病灶(dogfood:工具违反自己的公约)

连续加沟通 / 覆盖协议后,活文档出现两处"过度治理"——正是 `$sop-audit` §5.1 头号该抓的:

- **STANDARD §1 把同一批安全底线讲了两遍**:10 条编号原则 + 一整块「工作协作闭环(查证→分流→调研→执行验证→收口)」内容大量重叠(反驳 / 说人话 / 分流各写两次)。
- **sop-audit 的「主线覆盖闸」从薄闸胀成状态机**:exp-030 立的是**薄**覆盖闸(6 行、防漏),但 exp-031 / 032 / 033 往上堆状态词分类学(覆盖 / 部分覆盖 / 冲突 / 缺失 / 偏离 / 过重)+ 判定优先级算法 + surface 适用性 + 报告装配校验,长到 50+ 行。**exp-030 自己就警告过**:"覆盖闸继续长项,就会反过来变成它本来要治理的过度 SOP"——被后三轮违反。

工具违反了自己 §1 元规则(别当规则机器人)+ §5.1(头号查过度治理)。

## 2. 做法(判据 = 改完能不能通过自己的 audit)

- **STANDARD 228 → ~150**:§1 双叙述合成一条主线——反驳(§1.3)、说人话(§1.5)各写一次,「查证→分流→调研→执行验证→收口」收进 §1.4 一条 flow、不再重复反驳 / 说人话;砍"八荣八耻"记忆钩子(自陈非载重)+ 自指元评论;高风险闸并进 §1.9;§5 查法收紧、去掉与 SKILL 的重叠。
- **sop-audit 114 → ~62**:删覆盖闸状态机,换成「别漏查这几条高频主线」短清单(honoring exp-030 的**本意**:防漏,不是背题);保留默认只读 / 头号查太重 / 每条带证据 / 五类 severity 映射 / 双轨报告 / 轻量收尾卡。
