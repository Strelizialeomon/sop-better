## 1. 触发:owner 把一段无脚手架会话当"好 SOP"端回来

## 2. 涌现的 SOP 实物(证据)

vpn-tutorial **零 sop-better 脚手架**,但 agent 手搓出:

- **本地 issue 工作流**:`docs/issues/`(README 索引 + `001/002/003` + 状态图例 + "一个一个处理")——把 issue+PR 工作流在"无 GitHub remote(且仓含服务器 IP 不宜公开)"的约束下手搓了一版。
- **先调研、再立 issue**:源头是一份 `docs/superpowers/specs/2026-06-25-banwagong-hardening-research.md`,每个 issue 都 `调研依据见 →` 指回它。**doc 厚、issue 薄**(§1.8 那个形状)自发出现了。
- **真·实证调研**(owner 点中的那条)。这份调研 doc 不是从训练直觉拍的方案,是去测了真环境:
  - SSH 上服务器、用 **vnstat 实测真实带宽峰值**给 Hysteria2 Brutal 填值(issue #002 明写 `⚠️ 填太高反而拖垮;旧记忆里东京午间测到 tx 34Mbit/s,可参考搬瓦工实测`——**没直接复用旧东京的 34 这个先验,而是要求去实测搬瓦工**);
  - 用 **bgp.tools** 找"跟搬瓦工同 ASN/同网段的大站"当 Reality dest(具体工具,不是泛泛说"挑个好域名");
  - 专设一段 **"纠正网上常见误读"**(CF 隧道出口 IP 到底变不变、Reality 不兼容 CDN……);
  - 收尾一段 **"诚实的坑(汇总)"**:"非银弹"、"验证一律测 TLS 数据层/真实吞吐,**不测 ping**(ICMP 干净是 GFW 限速的伪装)";
  - 挂 **6 条真 Sources**(URL)。

**反例对照(实证的价值,本案里就摸得到)**:Hysteria2 的 Brutal 拥塞控制按固定速率硬发,**带宽填错(尤其填高)→ 速度反而崩**。若 agent 当时偷懒、直接用"旧东京 34Mbit/s"这个训练/记忆先验拍下去,而搬瓦工真实峰值不同,就是一个现成的翻车。这份调研 doc **靠"去 vnstat 实测"主动避开了这个 footgun**——"实证 vs 复述"的差别在这案里不是抽象,是一脚踩空和踩稳的差别。

## 3. 比对 STANDARD:哪些已覆盖,真 delta 是哪条

诚实拆开——大半是现有公约 + superpowers 已经在管的:

| 涌现的好东西 | STANDARD 里对应的 |
|---|---|
| 本地 issue 工作流 | §3 恒定流程 `issue+PR`(本地文件版只是"无 GitHub"下的右尺寸适配) |
| doc 厚 issue 薄、issue 指回 doc | §1.8 凭据(issue 薄、doc 厚 + 链接指过去) |
| 列三档方案 + 讲权衡 + 点盲区 | §1.10 主动建议(列选项+讲权衡+点盲区·照亮不代选) |
| "诚实的坑 / 非银弹 / 不 oversell" | §1.4 反驳协议(E 标未验、不空夸) |
| 说人话(满篇比喻:"TCP 一丢包就以为网堵了自己降速") | §1.7 说人话 |
| issue 带"验收标准"段 | §1.3 spec 验收可检验 |

**真 delta(STANDARD 现在没有的那一条)**:§1.10「主动建议」只规定建议的**形状**(列选项+讲权衡+点盲区),**从没规定建议的来源——"得落在对真实环境的实证调研上,别从训练直觉拍"**。"实证调研先行"这条,恰好是 sop-better **对自己**反复学到的那条元教训的**项目面孪生**:

- exp-002:`真跑 > dry-run`——结构上看不出的矛盾,真跑一次就现形;
- exp-013:静态全绿,**真复跑** py-script audit 才逮出删除残留;
- exp-014:改生成器前**先 verify-by-running 现状**——现状可能已是你要造的东西。

**sop-better 给自己上了"别在脑子里对、去真跑"这条闸,却从没把它灌进 `/sop-init` 生成给别人的 SOP 里。** vpn-tutorial 无意中演了一遍"项目版的真跑>dry-run":别在脑子里设计方案,去摸真环境再设计。这个**对称(自用 vs 下发)**是本条最值得记的发现。

## 4. 反方:为什么先**别**改 STANDARD(§1.4 B,先出最强反对)

1. **最强反方——它在零护栏下自己冒出来了**。STANDARD 的活儿是给"不会自动发生的好行为"上闸(§1.4 反驳就是铁证:作者亲测"写完禁止讨好下一条仍空夸",不上闸管不住)。而"实证调研先行"在 vpn-tutorial **没有任何 sop-better 脚手架**时照样发生——多半来自 `superpowers:brainstorming` + 模型自身判断 + owner 全局 `~/.claude/CLAUDE.md`(说人话等)+ 一个本就重视调研的 owner。**会自动发生的行为再立规矩 = 教科书级过度治理(§5 头号罪)。**
2. **N=1,而且是正面轶事,不是事故**。改 STANDARD 的两条线都没够着:
   - §3.5 默认:`复发 2+ 次才改规矩,别为一个数据点改标准`;
   - "一次就改"carve-out 的两关(exp-004/007/008/009 立的):**设计缺陷**(可证、不靠 N)+ **代价不对称**(便宜修 vs 昂贵复发)。这里**没有失败可定价**——§1.10"准许 armchair 列选项"算不算"导致伤害的设计缺陷"无实锤(本案恰恰没翻车),代价那关也无从定价。两关都没过硬。
3. **过度机械化风险真实**:把"必须先实证调研"写成硬闸,容易变成"每个小活都要先调研"的仪式,正撞 §3.5 反向齿轮 + 元规则(地板不是天花板)。

- **候选 delta(留着,别现在落)**:§1.10 可能欠一句"建议/方案要有实证背书——摸真实环境/实测/查真源,别从训练直觉拍";它是 exp-002/013/014「真跑>dry-run」的项目面孪生。

  - **邻近但不算数的**:exp-008(media-ops #60→#62,agent 裸写 stdlib)是 **house-style 参数缺位**导致,不是"armchair vs 实证"的同一个洞,别混算。
