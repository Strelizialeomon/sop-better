# exp-007 · 决策闸 issue 被「裁决即关」误关:SOP 规则本身指错

- **日期**:2026-06-09
- **真实任务**:media-ops issue #25(标题「【业务方决策】小红书私信走 web 还是 App——取决于客户账号类型(P0 私信路线闸)」)被业务方 Renan966 手点关成 COMPLETED,owner 发现是误关、要求重开,并问"这能不能靠 SOP 优化解决"。借这次真事故对 media-ops 跑 `/sop-audit` 验缺口。
- **本次撒手档位**:N/A —— 不是主动撒手实验,是**真用 SOP 时撞出的洞**(同 exp-002/004:真跑 > dry-run)。

## 1. 现象

- #25 是道**决策闸**:私信走哪条路,取决于"客户账号类型"——业务方拍 A(专业号/KOS 够);但 A 路能不能自动化,**还押在一个没跑完的 spike #31**(pro 私信通能不能稳定读+回)上。issue 正文「开发下一步」写了退出条件("spike 实测能读+回 → 关 A;跑不过 → 转 B 重议")。
- 业务方拍完 A,**手点关成 COMPLETED**(2026-06-08);spike 真跑数据没出。owner 次日扫到、手动 reopen。
- 表层像"人手滑"——但 audit 一查,**是 SOP 规则把人领过去的**。关闭执行者 `Renan966`(type User · 即 issue 点名"@Renan966 待你拍"的业务方)。

## 2. 根因:不是人手滑,是 SOP 规则指错

media-ops 工作流 doc 决策类 issue 段:「决策类 issue(标题带【业务方决策】)无验收环节——**裁决落 ADR + 关闭即完成**」。

- 这条把**所有**决策当"拍了就完",没有"**决策闸 = 裁决后还要等下游 spike/数据验证才收口**"的子类。#25 标题明写"(P0 私信路线闸)"、作者已感知它是闸,但 SOP 没给"闸"和"纯裁决"不同待遇 → 套"裁决即关"就提前关。**关它是合 SOP 的、不是违反**(同 exp-004:最强规则指向错误动作)。
- 三道本该兜底的全没接住:①决策类规则本身就是祸根;②「关前自检」只查 **label 卫生**(推终态 / 清 flag),不查"底层条件真满足没";③业务方「收件箱扫描」开工捞【业务方决策】**催人去拍**,拍完最自然的动作就是关 → 反把人推向关。
- 决策 issue「无验收环节」→ 退出条件只活在正文散文里、没有结构化字段 → 误关后 audit/sync agent **无法机检**。这次纯靠 owner 碰巧扫到才 reopen。

## 3. 关键判断:为什么"一次"就改(顶 §3.5「复发 2+ 次才改规矩」)

- **设计缺陷**(非调参数据点):"裁决即关"在构造上装不下"闸"、还把人导向误关——可证、不靠 N(同 exp-004)。
- **代价不对称**:修 = 工作流加一格子类 + 一句拦人;复发 = 一条 P0 路线闸被假关,下游当 A 已坐实往前走,白跑 / 返工。
- **边界**:仅决策闸(裁决选了路、且有下游 gating 验证);纯裁决(选型这种拍完即定)照旧"裁决即关",别滥扩。
- owner 拍板:采纳(3→2:先 audit 验、真了再改)。

## 4. 修复(本次 · 仅 sop-better 母本)

- **`templates/issue-pr-workflow.md`「关」步**:加决策闸 carve-out(裁决≠收口:正文写关闭条件 + 给人「只回复决策、别关 issue」+ 裁决后 label 不进终态、挂 spike 上)。
- **`STANDARD.md §5` + `skills/sop-audit/SKILL.md §4`「凭据失真 / 交接断裂」**:加查"决策闸被裁决即关(closed 但关闭条件未满足)"。
- **过 exp-005 自审**:不重抄(§1.8 凭据保真是通用、这里是新增"裁决≠收口"子类 + 纠"裁决即关"过简);可指针(carve-out 引 §1.8、不复述);净增小(template ~1 子条、STANDARD/SKILL 各 1 句);不立新公约 / 状态机 / 新 label。

## 5. 抽一条教训 → 回填 PLAYBOOK

决策 issue 要分两类:**纯裁决**(拍完即定 → 裁决即关)vs **决策闸**(裁决只选了路、收口要等下游验证落定 → 别在裁决时关,写关闭条件 + 拦人误关 + 裁决后 label 不进终态)。把这俩混成一条"裁决即关"= 把选路当收口 = 说谎凭据。
