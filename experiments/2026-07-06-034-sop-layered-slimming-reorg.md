# exp-034 · SOP 三层瘦身重排

- **日期**:2026-07-06
- **真实任务**:短时间多轮迭代后,对 sop-better 本仓 SOP 做一次无语义新增的逻辑理顺和瘦身重排
- **本次撒手档位**:L3(SOP 核心规则表达重排,影响 STANDARD / master / sop-audit)

---

## 1. 选活 + 定档

用户明确指出:多轮需求叠加后,SOP 容易变成一层层补丁。对 agent 来说不是字越多越好,而是越精准越好。

爆炸半径:

- 写太轻:只删字,不解决权威 / 执行 / 审计混在一起的问题。
- 写太重:借瘦身之名新增规则、拆新文档、制造新漂移源。
- 最危险:压缩时把反驳、凭据保真、高风险闸、主线覆盖闸等承重墙删掉。

本轮定 L3,但限制为**无语义新增重排**。

## 2. 便宜验证方案(动手前必须答)

> 我怎么在 20 分钟内、不逐行读,就看出 AI 做对没?

- 验证 `STANDARD.md` / `skills/sop-audit/SKILL.md` 的超长段是否明显下降。
- 验证 `$sop-audit` 是否仍是固定 6 行主线覆盖闸,没有第 7 项。
- 用承重墙矩阵确认关键护栏仍有权威点 / 执行点 / 必要审计点。
- 用 `media-ops` 只读压力样本复核 Refs/Closes、三件套、issue 评论分层、高风险治理项、结构触发没有因瘦身漏掉。
- 过独立新眼睛 review,重点查无语义新增和护栏未丢。

如果答不上来,先补的是验收矩阵,不是继续删字。

## 3. 给 AI 的简报(只给目标+约束+验收,不给解法)

```text
目标:
把 sop-better 从补丁堆叠整理回三层承载:STANDARD 权威层、master 执行层、sop-audit 审计层。

约束:
无语义新增;不新增 skill;不新增主线覆盖项;不拆新权威文档;不改跳 writing-plans;不弱化主线覆盖闸。

验收标准:

```

## 4. AI 跑完,我来评

- **AI 做了哪些决策**:
  - 把 `STANDARD.md` 的事故解释和执行细则压成原则 / 边界 / 指针。
  - 把 `$sop-audit` 的模板漂移和主线覆盖说明拆成顺序检查块。
  - 只轻触 `master/base/AGENTS.md` 和 `issue-pr-workflow.md`,保留执行入口。
  - 按独立 review 反馈补强 spec 的实验必做、三层不替代两层、承重墙矩阵、治理 doc 风险分流。

- **超出我预期 / 我自己想不到的地方**:
  - “三层”容易被误读成替换“两层模型”这一点由新眼睛指出,及时补进 spec。
  - grep 关键词不够,要看权威点 / 执行点 / 审计点矩阵,比单纯查词更能防瘦丢护栏。

- **翻车 / 我得纠偏的地方**:
  - 首版 spec 把 `experiments/` 写成可选,和本仓自举纪律冲突;已改为必做。
  - 首版验收只写普通文档别误判高风险,漏了治理 doc 不能误放低风险;已补。
