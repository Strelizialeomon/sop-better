## 1. 选活 + 定档

media-ops 已在真项目里遇到过 issue 评论过短的问题:spike / 实测 / 收口这类高价值评论如果只写一句进度,后续 agent 无法独立判断。

这不是 media-ops 私有细节,而是所有把 issue 当共享内存的项目都会遇到的问题。爆炸半径是:评论写短后,状态 / 证据 / 边界 / 残项丢失,后续 agent 会凭不完整凭据继续执行。

```
- 厚评论最小信息覆盖状态、动作、证据、判定、边界、残项、下一步。
- 短评反向边界明确:改变验收、风险、范围、状态、决策、残项、路线或关闭条件时不得短评。
- AGENTS 只有短引用,不复制长标准。

```
