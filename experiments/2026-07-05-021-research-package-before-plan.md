# exp-021 · 方案前调研包

- **日期**:2026-07-05
- **真实任务**:用户重新评估“网络调研后再给方案”的 SOP,指出旧版“方案前证据优先”不符合预期。
- **本次撒手档位**:L3(改 STANDARD / 母本 / audit 规则,影响后续项目生成与审计)

---

## 1. 选活 + 定档

这不是单个项目的喜好,而是 owner 的稳定工作习惯:方案 / 设计 / 估算 / 选型前,希望 agent 先查真实情况和主流做法,再给建议,别凭训练记忆拍脑袋。

旧版 exp-021 已把规则落成“方案前证据优先”,但用户复盘后认为它不够:它只要求方案有依据,没有要求 agent 最少交付“建议方案、主流解决办法、可靠信源”。用户进一步澄清:信源不必大段展示,官方也不一定永远正确;信源的目的主要是证明 agent 真调研了,不是瞎猜。

因此本次仍沿用 exp-021,把结论修正为“方案前调研包”。影响 `STANDARD.md`、`master/base/AGENTS.md`、`$sop-audit`、spec 和 PLAYBOOK,所以按 L3。

爆炸半径:

- 写太轻:agent 继续先给泛泛方案,末尾补一句“有依据”,仍然像拍脑袋。
- 写太重:每个小改都要长篇调研包,拖慢节奏,违反右尺寸。

## 2. 便宜验证方案(动手前必须答)

- 如果上面答不上来 → 先补的功课是:把调研包五件套写进 spec,别只写“证据优先”口号。

## 3. 给 AI 的简报(只给目标+约束+验收,不给解法)

```
目标:
把“方案前证据优先”改成“方案前调研包”:给方案 / 设计 / 估算 / 选型 / 外部平台接入前,先输出调研结论、主流做法、建议方案、信源凭据、未验证风险。

约束:
- 不新增独立 skill。
- 不改外部 superpowers 插件缓存。
- 不把信源凭据变成堆链接。
- 必须保留低风险局部补丁 / 纯解释 / 稳定常识 carve-out。
- 规则要进 STANDARD / master/base/AGENTS.md / sop-audit。
- PLAYBOOK 必须由本实验背书。

验收标准:
- STANDARD 和母本使用“方案前调研包”。
- 调研包包含:调研结论 / 主流做法 / 建议方案 / 信源凭据 / 未验证风险。
- 信源凭据强调可靠来源支撑,不迷信官方,博客 / issue / SO 只能当线索或低可信补充。
- audit 能查缺失,也能防“所有任务强制调研包”的过度治理。
```

## 4. AI 跑完,我来评

- **AI 做了哪些决策**(它替我想的部分):
  - 把规则命名从“方案前证据优先”改成“方案前调研包”。
  - 把交付物钉成五件套:调研结论、主流做法、建议方案、信源凭据、未验证风险。
  - 弱化“官方信源展示”,改成“可靠信源凭据”:展示可以短,但推荐必须有可靠来源支撑。
  - 保留 carve-out:小改 / 纯解释 / 稳定常识 / 无环境可摸不强制调研包。
- **超出我预期 / 我自己想不到的地方**(← 爽感来源,最重要):
  - 用户澄清“官方有时也不一定都对”后,规则从“官方链接优先展示”变成“可靠来源支撑建议”,更贴近真实调研。
  - 这条比旧“证据优先”更容易 audit:缺主流做法 / 建议方案 / 信源凭据 / 未验证风险任一,都能指出来。
- **翻车 / 我得纠偏的地方**:
  - 旧版把用户需求压成了质量标签,没有钉交付物形态;这会让 agent 继续先拍方案再补依据。
