# exp-025 · 沟通闭环瘦身重排

- **日期**:2026-07-05
- **真实任务**:短时间连续加入三层引导、方案前调研包、任务收口卡、诚实无知闸后,用户要求彻底检查并优化 SOP,避免叠床架屋。
- **本次撒手档位**:L3(改 STANDARD / 母本 / sop-audit / README / PLAYBOOK,影响后续项目生成与审计)

---

## 1. 选活 + 定档

这不是单条规则对错,而是规则组织方式开始变厚。审计发现:新增规则大多是对的,但在常驻母本里横向并排成多个协议名,agent 要自己判断“现在到底用哪条”。这会让 SOP 从“精确指令”滑向“背条款”。

用户选择 A 档方案:**瘦身重排,不改语义**。不删真实事故换来的护栏,只把现有规则收编成一条运行时闭环。

爆炸半径:

- 写太轻:只是改标题,并列协议仍旧堆着。
- 写太重:误删刚验证过的护栏,尤其反向边界和高危闸。
- 写歪:把 STANDARD 的细则搬空到母本,导致审计没真相源。

## 2. 便宜验证方案(动手前必须答)

## 3. 给 AI 的简报(只给目标+约束+验收,不给解法)

