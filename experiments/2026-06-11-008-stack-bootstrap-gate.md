# exp-008 · 立栈被 agent 自决:实现级技术路线没有确认点,owner 反向 900 行重铺

- **日期**:2026-06-11
- **真实任务**:media-ops #60(D1 第一份产品代码:Go 服务骨架)→ #62(重构:server/ 对齐 go_dispatch 结构与依赖)。owner 反馈"agent 没和我确定技术路线就开干,我后面又反向人工去约束",问能否在 sop-better 优化。
- **本次撒手档位**:N/A —— 不是主动撒手实验,是**真用 SOP 时撞出的洞**(同 exp-002/004/007:真跑 > dry-run)。

---

## 1. 现象

- #60 动工前,**方向级**路线是有闸的:Go + DrissionPage 双进程,ADR-0008 + spike #58 闸门过,owner 已拍。
- 但**实现级**技术路线(用什么框架 / 项目布局 / 核心依赖)agent 自决了:裸写 stdlib 版(net/http + database/sql),~900 行。
- owner 脑中其实有既定 house-style:个人 Go 项目标准 `go_dispatch_backend`(gin/GORM/viper/zap + 固定布局)。事后只能开 #62 反向重铺,把 D1 全部既有能力等价迁移一遍。

## 2. 根因:三个叠加的洞(不是缺一条规则)

1. **已有规则挂错钩子**:media-ops CLAUDE.md 写了"开发角色:和我确认技术方案/架构",但它挂在「梳理思路:用 brainstorming」名下。D1 的活从 issue/roadmap 流下来、走"spec 通过后直接实现",brainstorming 不触发 → 确认规则跟着哑火。
2. **最强规则指向错误动作**(exp-004/007 同形):「能自决就自决、别假民主、不列方案让我 pick」+「怎么做归 AI」→ agent 选 stdlib 裸写是**忠实执行**,不是违反。自决口诀的"要重做/涟漪出去 → 找人"理论上覆盖立栈(立错就是重做,#62 实证),但 greenfield 起步时"还没东西可涟漪",agent 识别不出 → 缺显式 carve-out。
3. **owner 的 house-style 是从没人问过的参数**:sop-init 只问 S/C/ends/risk,从不问"有没有既有技术规范/参考项目" → 这条约束从未落进项目凭据,agent 无从知道。

## 3. 关键判断

### 为什么"一次"就改(顶 §3.5「复发 2+ 次才改规矩」,过两关)

- **设计缺陷**(非调参数据点):规则可证指错(自决条款主动指向"自己选栈")+ 参数表结构性缺位——不靠 N 成立。
- **代价不对称**:修 = 规则文件净增 ~4 行;复发 = 每个新端/新栈起步都可能 ~900 行重铺 + 一轮反向纠偏。
- owner 拍板:采纳方案 C(参数 + 确认闸),闸取**阻塞等拍板**形态(立栈低频、一次性、定了难改,等一轮值得;异步可毙 = 毙时代码已长出来,重演 #62)。

### house_style 必须指参考仓本体,不指快照

#62 正文 owner 原话:"hi_gin 技能已过时,以项目本体为准"——技能/记忆快照会漂移(同 §1.8 凭据保真逻辑)。所以参数指**参考仓本体**;sop-init 可给推断候选但**必须 owner 确认、不静默凭记忆填**(exp-002 的"凭记忆填空偷带旧习惯"同源)。

### 防闸变仪式(过度治理反方,写死边界)

闸只管**新端/新服务起步**的基建选型(语言/框架/项目布局/核心基建依赖如 ORM/配置/日志);既有栈内加常规依赖/库 = 照旧自决。不许扩成"每个依赖都来问"。

## 4. 修复(本次 · sop-better 母本)

- **`STANDARD.md §1.9`**:自决口诀下加「🏗 立栈不算边界细节」carve-out(有 house_style → 直接对齐 = 定义层零人成本;无 → 可扫提案〔每决策 + 一句理由,exp-001 形态〕阻塞等 owner 拍板)。挂在自决规则上 = 在**实现路径**上生效,不依赖 brainstorming 触发(治洞 1+2)。
- **`STANDARD.md §2` 参数表**:加 `house_style[]` 行(治洞 3)。
- **`STANDARD.md §5.4` 结构缺失**:查项清单加"立栈闸与 house_style 落点"(audit 模板版本差比对自动逮老项目缺位;sop-audit SKILL 指针引用 §5,不用动)。
- **`templates/agent-constraints.md` 标准块**:加一行「立栈先对表」(带 `{{house_style}}` 占位,只给指令、不复述论证)。
- **`skills/sop-init/SKILL.md` 参数**:加 `house_style[]` 询问(指仓本体 + owner 确认两条纪律)。
- **过 exp-005 自审**:无新章节 / 新品牌概念(carve-out 并进 §1.9);template/SKILL 不重抄论证;规则文件净增 ≤10 行(实测见 PR)。
