# exp-022 · 任务收口卡协议

- **日期**:2026-07-05
- **真实任务**:用户复盘 Codex 使用体验:需求做完或事情办完后,agent 没有稳定的收口闸,不主动说明下一步、验证、风险和是否可结束。
- **本次撒手档位**:L3(SOP 核心沟通规则调整,影响 STANDARD / 母本 / audit / PLAYBOOK)。

---

## 1. 选活 + 定档

这次不是新增功能,而是修 SOP 的协作体验缺口。已有 exp-020 解决“开工前怎么引导”,exp-021 解决“给方案前怎么调研”,但结束时还缺一条默认闸。

爆炸半径中等:写重了会让每个小回答都变成长流程;写轻了继续没有收口感。影响所有后续生成项目,所以按 L3。

## 2. 便宜验证方案(动手前必须答)

> 我怎么在 5 分钟内、不逐行读,就看出 AI 做对没?

- 验证手段:`rg` 查 STANDARD / 母本 / PLAYBOOK 是否出现“任务收口卡 / 小事一句话 / 普通任务五件套 / 推荐不等于授权”;查 `$sop-audit` 是否把它纳入 §5.3 沟通约束。再用 5 个场景反推是否过度治理。
- 如果上面答不上来 → 先补的功课是:把收口卡拆成小事一句话、普通任务五件套、高风险决策收口卡,避免一刀切。

## 3. 给 AI 的简报(只给目标+约束+验收,不给解法)

```text
目标:
把“任务做完后要帮 owner 收口”落成可检查 SOP。

约束:
- 强引导默认 A:每件事结束都要有收口动作。
- 小事压缩成一句话,不要把所有回答都变成长流程。
- 普通任务至少交代状态、验证、风险、推荐下一步。
- 有真分叉才给 2-3 个快捷选项。
- 高危动作仍要 owner 明确授权。

验收标准:
- STANDARD / AGENTS 母本 / sop-audit 都有落点。
- PLAYBOOK 有 exp-022 背书。
- 反向边界保留:纯解释、小事不强制长卡片;推荐 push / deploy 不等于授权。
```

## 4. AI 跑完,我来评

- **AI 做了哪些决策**:把规则命名为“任务收口卡协议”;拆成小事一句话、普通任务五件套、高风险决策收口卡;把“推荐不等于授权”写成边界。
- **超出我预期 / 我自己想不到的地方**:把它和三层引导、方案前调研包串成“开头引导、中间调研/自检、结尾收口”,形成完整协作闭环。
- **翻车 / 我得纠偏的地方**:需要防止 agent 把它执行成长篇模板,所以必须写反向边界和 audit 过度治理检查。
