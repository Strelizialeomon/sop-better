# exp-049 · 步进-点头闭环:agent 自报下一步,owner 一字放行(治"做完一步就趴窝")

- **日期**:2026-07-23
- **触发**:owner 澄清「loop」真实含义——不是 agent 无人循环,是**步进**:SOP 对下一步有计划时,agent 做完上一步就该自己知道并报出下一步;owner 只想点头,不想当"下一步复读机"。
- **决策**:方案 B(纸 + 双状态锚),设计 spec 见 `docs/specs/2026-07-23-step-gate-loop-design.md`(owner 已终审);方案 C(Stop hook 机器兜底)按「先纸后机器」排队。

---

## 病根(接 exp-048)

SOP 有流程但没有"当前位置":流程以散文清单散在 3 个文件(base 闭环一句 / 端速查 5 步 / 6+1 骨架),agent 靠几十轮前的记忆自我定位,注意力一稀释就趴窝等喂。**就算把 SOP 减到 20 行,这个病照样在**——厚度(另由 sweep/遗产清查治)和断链是两个病。

## 做法(全落已合 PR,见 spec §四)

- `issue-pr-workflow.md`:新增「步进-点头」节——权威 6 步表(取活→细化→实施→验证+复审→交付→收口),每步带完成判据 + 过闸报告话术;批量放行(「连走到 X」);高风险闸独立。
- **双状态锚(主从定死)**:issue 流程勾选框 = 真相源(跨会话定位),会话任务清单 = 投影(每轮自动在 agent 眼前,不吃注意力衰减);不一致以 issue 为准,回退步骤须评论说明。
- `master/base/.github/ISSUE_TEMPLATE/`(新母本资产):task / bug 模板自带「流程」勾选框节;`$sop-init` 项目确认用 Issue 时连带生成,仍不无条件预建。
- `base/CLAUDE.md` +1 规则行(步进-点头);`end-role-claude.md` 端速查 5 步散文降为指针 + 端内注记。

## 出题税结算

+1(步进-点头规则行)− 1(端速查流程散文降指针,删一处重复流程),净约持平偏负,税缴清。

## 验收(owner 已拍 · 待一周实跑回填)

1. 会话内:每步末尾必有"下一步是 X"报告,停等放行;
2. 跨会话:新会话接手半截 issue 能从勾选框定位续走;
3. owner 体感:跑一周,输入只剩"嗯 / go / 连走到 X"。

## 未验证 / 风险(诚实标坑)

- 「接活先展开任务清单」首动作仍是 nudge,失守则会话内锚失效(跨会话锚仍在)——正是排队的 Stop hook 要兜的洞。
- 6 闸/任务是推测的舒适密度,实跑嫌烦 → 调稀(如默认"连走到交付")属参数调整不动架构。
- 步进表(单 agent 任务级)与 6+1 骨架(跨端协调级)两个视角本期不合并,实跑混淆再互指。
- xhs 模板补流程节另走小 PR;其余 lab 项目随 #15 sweep 回灌。
- **PLAYBOOK 暂不回填**:等一周验收数据回来、真验过了再结晶(自举闭环的"验透"关)。
