# exp-011 · 「说人话」一直是口号、从没上闸——反驳那半边落了 6 闸,说人话这半边漏了

- **日期**:2026-06-23
- **真实任务**:owner 反映"用了本 SOP 的项目,跟我聊需求时语言不通俗"(满嘴术语 + 一大段没重点为主),让我回头审 SOP 自己的「说人话」这块能不能优化。
- **本次撒手档位**:N/A —— 不是撒手档位实验,是 **owner 观察 + 结构缺陷**驱动的 SOP 自审(同 exp-005/006 形态)。

---

## 1. 现象(缘起)

- owner 实测:多个用本 SOP 的项目,在**需求沟通**环节对人输出不通俗。圈定的两个症状——**① 满嘴术语/黑话不解释;② 信息堆成一大段、不结论先行**(第三个"聊需求拽人抠技术"owner 判没那么严重,属另一根轴 §1.2,本次不动)。

## 2. 根因:约束块自己许诺了"闸",却只对反驳兑现、对说人话没兑现

- 生成进每个项目 CLAUDE.md 的「沟通约束块」(`templates/agent-constraints.md`)**块头亲口承诺**:「"要客观""要说人话"都是口号、管不住;下面是**可检查的闸,过不去不许放行**」。
- 往下看:**反驳**那半边兑现了——6 条都是**能逐条判违规、可观察**的硬闸(出现"完美"不跟理由 = 违规……);**说人话**那半边没兑现——4 条还是**软口号**(少黑话、往简单了说……),没有触发点、没有"= 违规"、没有"过不去不许放行"。**等于块头自己定的标准,反驳达标、说人话没达标。**
- 这正是 `STANDARD §1.4` 早记下的血泪教训(作者亲测:写完"禁止讨好"下一条仍在空夸)的**同形复发**——光靠态度/口号管不住,必须做成**强制产出 + 过不去的闸**。反驳照这条做了所以生效;说人话从没被提到这条标准上,所以漏。owner 圈的两个症状(黑话、大段)恰好就是那 4 条**点了名却没上闸**的事。

## 3. 关键判断

### 为什么"一次"就改(顶 §3.5「复发 2+ 次才改规矩」,过两关)

- **设计缺陷(非数据点)**:约束块**内部自相矛盾**——块头承诺"可检查的闸",说人话小节却只给口号。可证地不达标,不靠 N。且 §1.4 已确立"沟通约束必须上闸"的原则,说人话只是从没被拉到这条线上。
- **代价不对称**:修 = 模板净增≈0(换不是加)+ STANDARD ~1 行;不修 = 每个用本 SOP 的项目都继续对人上黑话/糊大段(owner 已证多个项目在发生),**直接背叛 SOP 自己的「说人话」公约**。

### 怎么改不变成"规则机器人"(关键张力)

- **闸是行为级、不是数字阈值**:照反驳的形态(「空夸即违规」这种可观察行为),不写"超过 N 句就违规"那种死阈值——死阈值会逼 agent 把闲聊也切碎、变刻意(撞 §元规则「别当规则机器人」)。
- **受众 carve-out 兜住过度套用**:三道闸**只管「给人看的」(对话/报告)**;给 agent 的 spec/issue/约束/凭据保持精确密度——防止 agent 借"说人话"把真相源 doc 也稀释掉(§1.7 措辞分受众)。
- **元规则仍在头上**:照字面会变差就按精神来 + 标记,owner 终裁。闸是地板不是天花板。

### 拍板点已解(那条兜底话没真丢)

- 软口号里"不确定就往简单了说"这条**没法判违规、进不了硬闸**,从模板删;但它作为**精神**仍活在 `STANDARD §1.7` 公约正文里。另两点("抽象配例子""命令/代码配旁白")折进黑话闸/大段闸没丢。**净丢 = 0 个可执行行为**,只是软兜底从模板挪回原则层。

### 诚实标注(比 008/009 弱在哪)

- **证据是 owner 观察 + 结构自相矛盾论证,不是带 issue 号的实锤事故**——比 exp-008/009(真事故复盘)grounding 弱。强在"约束块自我矛盾"可证、不靠事故严重度。
- **over-mechanization 风险真实**:硬闸可能让 agent 在轻量对话里显得刻意/碎念。靠 carve-out + 元规则兜;**若复用中发现 agent 变机器人式碎句,回炉把闸收软或降级。**
