# exp-045 · SOP 有工具层边界:用户手点的技能(grill-me)压过 §1.3 结论先行,SOP 治不住——态度规则落最轻的家、别当承重墙

- **日期**:2026-07-20
- **问题**:mobile-os #110 讨论里用户手打 `/grill-me`,我把 challenge 做成车轮战、把该我做的思考拆成问题甩回,用户当场反感"总被当考官"。追因发现 STANDARD §1.3「先反方后结论」本就在、却没拦住。
- **目标**:定位"为什么 SOP 没拦住 + 正确落药层";顺带回答 owner 追问"SOP 不是万能 → 是否该更轻薄"。
- **边界**:只加全局 CLAUDE.md 一条 nudge + 本实验;**不动 STANDARD 一个字**(理由见 §3)。

---

## 1. 病灶(两层没打通 + 态度规则没闸)

- **工具层压过约定层**:grill-me 的「relentless interview」写在**它自己的定义文件**里(`disable-model-invocation: true` / `allow_implicit_invocation: false`——AI 永远没法自选,只能用户手点触发)。用户手打 `/grill-me` 那刻 = 当场用工具 override 掉 STANDARD §1.3。**SOP 是文档/约定层,伸不进一个技能的文件。**
- **拦它的规则本就在、却是没闸的态度**:§1.3「先反方后结论」要的正是"给结论 / 推荐",grill-me 恰恰只问不给。但 §1.3 对"别 quiz"没有可检查闸——按 §1.3 自己那句"'要客观'是口号、必须落成可检查的闸",它对付 grill-me 时**自己也还是口号**,只 nudge 不保证。
- **per-project 记忆治不了跨项目**:mobile-os 早存过 `challenge-not-quiz.md`,但它是项目级、在 sop-better 会话不加载 → 老坑跨项目重演。

## 2. 做法(分层下药,最自洽的是"这次别动 STANDARD")

- **SOP 层(吃 80%)**:全局 `~/.claude/CLAUDE.md` 加一节「反驳 / 打磨:给推荐、别当考官」——管日常误伤,对所有项目生效。**放全局、不放 sop-better 的 STANDARD**:它是纯态度 nudge、落不成硬闸,按 §3 结晶该进"最轻的家",不给在造的 SOP 增重。
- **工具层(剩 20%,SOP 够不着)**:要么想协助时别点 `/grill-me`(选工具);要么改 grill-me 本体让每轮结尾必须落一条推荐(改工具文件)。二者都不在 SOP 能触及的范围——诚实承认边界,不假装 SOP 能焊死。
- **STANDARD:零改动**。这次没冒出缺的承重墙;往 STANDARD 加"SOP 不是万能"的元评论,本身就是它头号要治的过度治理(exp-040 血泪)。用"这次不给 STANDARD 加东西"本身,演示"薄是默认"。

## 3. 结晶(候选回填 PLAYBOOK)

**SOP 不是万能——但答案不是"整体更薄",是"分层诚实 + 更狠的入场测试"。**

- **入场测试**:一条规则进 SOP 前先问「它能落成**可检查的闸**吗?」能 → 做成闸;纯态度、落不成闸 → 它只是 nudge,进**最轻的家**(全局 CLAUDE.md 一行),别在 STANDARD 当承重墙供着,并诚实标"只推不保证"。
- **SOP 有边界**:够不着工具层(技能 / hook 由它们自己的文件定)的问题,别硬塞进 SOP。对"一有摩擦就加一条 SOP"的反射踩刹车——这才是"不是万能"该导出的动作,**不是无差别减重**(无差别减重会误伤承重墙,exp-006 / 040 已立此戒)。

## 4. 未验证 / 风险

- **nudge 仍只是 nudge**:全局 CLAUDE.md 这条没有硬闸,下次 grill-me 或 AI 上头时能不能真拦住,未验——靠用户喊停兜底。诚实说,这条永远带一点"靠口吻自觉"。
- **「入场测试」未落成工具**:目前只是判断原则,没有 audit 维度去自动查"某态度规则是否被误当承重墙"。若要升闸是 `$sop-audit` 的后续活,本次未做。
- **PLAYBOOK 去重未做**:结晶条与 exp-011 / 040 的边界待 owner 核,避免近义重条。
