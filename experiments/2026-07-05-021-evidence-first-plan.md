# exp-021 · 方案前证据优先

- **日期**:2026-07-05
- **真实任务**:用户反馈自己倾向让 agent 网络调研后再给方案,要求判断能否优化到项目 SOP。
- **本次撒手档位**:L3(改 STANDARD / 母本 / audit 规则,影响后续项目生成与审计)

---

## 1. 选活 + 定档

这不是单个项目的喜好,而是 owner 的稳定工作习惯:方案 / 设计 / 估算 / 选型前,希望 agent 先摸真实情况,别凭训练记忆拍脑袋。

已有基础:

- exp-015 记录无脚手架项目自然长出“实证调研先行”。
- exp-016 已把“实证 + 信源可信 vs 拍脑袋”放进 spec 新眼睛审查。
- 用户级全局指令也明确“给方案前先调研真实情况”。

本次新增点:把它从 **spec 收口后的审查项** 前移成 **方案产出前的行为闸**。影响 `STANDARD.md`、`master/base/AGENTS.md` 和 `$sop-audit`,所以按 L3。

爆炸半径:

- 写太轻:agent 继续先给泛泛方案,之后才发现没查真环境 / 真规则。
- 写太重:每个小改都要联网调研,拖慢节奏,违反右尺寸。

## 2. 便宜验证方案(动手前必须答)

> 我怎么在 5 分钟内、**不逐行读**,就看出 AI 做对没?

## 3. 给 AI 的简报(只给目标+约束+验收,不给解法)

```
目标:
让 agent 给方案 / 设计 / 估算 / 选型前先摸真实情况,但不要把所有小事都变成联网调研。

约束:
- 不新增独立 skill。
- 不改外部 superpowers 插件缓存。
- 不把“多调研”写成空口号。
- 必须保留低风险局部补丁 / 纯解释 / 稳定常识 carve-out。
- 规则要进 STANDARD / master/base/AGENTS.md / sop-audit。
- PLAYBOOK 必须由本实验背书。

验收标准:
- 方案前证据优先进入 STANDARD 和母本。
- 规则区分本地真实状态和外部网络调研。
- 信源分档:实测 / 官方 / 源码 / 规范优先,issue / SO / 博客只当线索。
- 输出方案时标依据 / 未验证 / 风险。
- audit 能查缺失,也能防“所有任务强制联网”的过度治理。
```

## 4. AI 跑完,我来评

- **AI 做了哪些决策**(它替我想的部分):
  - 把规则命名为“方案前证据优先”,不是“网络调研优先”。
  - 把证据来源分成项目内实测和外部一手源,网络只是其中一类。
  - 把输出要求压成一句“依据 / 未验证 / 风险”,避免写成研究报告仪式。
  - 把 carve-out 写清:小改 / 纯解释 / 稳定常识 / 无环境可摸不强制调研。
- **超出我预期 / 我自己想不到的地方**(← 爽感来源,最重要):
  - 外部调研反而支持“别一刀切”:OpenAI 文档区分快速搜索、agentic search、deep research;Anthropic context engineering 强调提示词要具体但不硬编码。
  - 这条和 exp-016 的关系更清楚:前置证据闸 + 后置 spec 新眼睛,不是重复。
- **翻车 / 我得纠偏的地方**:
  - 未来 audit 可能把“没联网”误报成问题;正确判据应是“方案依据有没有真实来源”,不是“有没有上网”。
