# sop-better

一个**私人撒手训练场 + 活的操作手册**。

不是工具,不是代码项目。它是一个结构化的日记本:你在真实任务上,一次次把"思考"往 AI 手里多塞一点,记录爽不爽、翻没翻车,然后把"什么能安全交出去"沉淀成手册。

---

## 这个项目要解决的真问题

> 用了 AI 之后,它确实能替我做更难、更多的事。但我没有爽感,也没感到飞跃性的效率提升——我还是在做开发,只不过现在不直接写代码而已。

**根因**(不是代码乱,是工作模式):

- 我习惯性自己扛下**全部认知决策**(设计、算法、取舍、字段、阈值),只把**打字**交给 AI。
- 累人的那 80%(思考)我一点没放手,卸掉的是最不累的 20%(打字)。所以当然还是"在做开发"。
- 从没真正试过把"设计/取舍"交出去。习惯 + 一点没审视过的不信任。

**更深一层**:我现有那套 SOP(细粒度、详 spec、跨端契约、逐 task review、audit)——**全是控制机制**。它为"正确 + 可审计 + 多 agent 协作"优化,不为"杠杆 + 爽感"优化。爽感在另一条线上:*AI 干了我没想到的事,而且还不错*。这种瞬间被我亲手从流程里工程掉了。

---

## 核心论点(整个项目绕着它转)

```
要爽感  →  得撒手,把"认知"交出去(不只是打字)
要敢撒手 →  验证必须便宜 + 爆炸半径有界
所以本项目 = 练习把认知安全地交出去,直到信任由证据换来
```

**为什么不敢撒手?根子不是"不信任 AI",是"验证太贵"。** 我没法便宜地检查 AI 的设计好不好,只能提前把一切控死。把验证做便宜 → 才敢撒手 → 撒手才有杠杆。

---

## 撒手梯子(把虚的"粒度"变成能拨的刻度盘)

每次实验,明确说这次站哪一格:

| 档 | 我交出什么 | 我保留什么 |
|---|---|---|
| **L0** | 只交打字 | 设计/方案/取舍全自己做 |
| **L1** | 交"细节决策" | 给方案骨架,AI 填肉 |
| **L2** | 交"整个方案" | 只给:目标 + 约束 + 验收,AI 设计我拍板 |
| **L3** | 交"什么算做完" | 只给目标,AI 拆解 + 设计 + 定义完成,我抽检 |
| **L4** | 交"做什么" | 给个模糊愿景,AI 提议做啥、自己框范围 |

**默认我在 L0。每次实验 = 从默认档往上挪一格,看会发生什么。** 爽感藏在没上去过的那几格里。

---

## 怎么跑一次撒手实验(5 步)

复制 `experiments/_TEMPLATE.md`,命名 `experiments/YYYY-MM-DD-NNN-名字.md`,然后:

1. **选活 + 定档** —— 真实任务;挑比当前默认高**一格**的档。
2. **先想好怎么便宜验证**(硬门槛)—— 动手前先回答:"我怎么在 X 分钟内、不逐行读,就看出 AI 做对没?" 答不上来,**这就是你要先补的功课**(测试?契约?缩小范围?)。
3. **下简报** —— 只给 AI `目标 + 约束 + 验收标准`,**绝不给解法**。
4. **AI 跑,你评** —— 给它的设计/决策打分,记下哪里超预期、哪里翻车。
5. **抽一条教训** —— 这次学到"什么能/不能在这一档交出去",回填进 `PLAYBOOK.md`。

## 成功长什么样

跑够 5~8 次实验后:

- 有过几次真实的"卧槽这样也行"瞬间(爽感数据点);
- `PLAYBOOK.md` 里攒出一套**你自己的**"什么活能放到哪一档、前提是什么";
- 你的**默认档至少上移一格**(从 L0 → 至少 L1/L2);
- 实验记录里的"省力 / 爽感"评分趋势向上。

## 不做(YAGNI · 故意留白)

- ❌ 不写任何工具 / CLI / 自动化 —— 没数据之前全是想象。
- ❌ 不搬多 agent 的契约 / coordination / audit 仪式 —— 那是控制机器,本项目要的恰恰相反:**留白给惊喜**。
- ❌ 不顺手修别的项目(三套 Go 目录、jotai 不统一……)—— 那是另一个项目。
