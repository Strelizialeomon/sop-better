# 步进-点头闭环(step-gate loop)设计 · exp-049

- **日期**:2026-07-23
- **需求一句话**:agent 按 SOP 干活时,做完流程中的一步,**自己定位并报出下一步、停等 owner 一字放行**——owner 从"下一步复读机"变"点头机";跨会话能接续;issue 收口后自动建议下一个任务。
- **背景**:exp-048 诊断——SOP 有流程但没有"当前位置":流程以散文清单散在 3 个文件,agent 靠几十轮前的记忆自我定位,注意力一稀释就趴窝等喂。厚度(实测单会话必载 ~200 行规则)是并发病,由 sweep/遗产清查另治;本需求只治步进断链。
- **方案选型**:B——纸 + 双状态锚。A(纯加规则行)= 再贴一张会被无视的纸条,不治病根;C(+Stop hook 机器兜底)按 owner「先纸后机器」拍板列为排队项。

---

## 一、验收(owner 已拍)

1. **会话内**:agent 完成流程任一步后,不等提示、自己报"本步完成 + 下一步是 X",停等放行;
2. **跨会话**:新会话 / 新 agent 接手半截 issue,能从 issue 流程勾选框定位"走到哪、下一步是啥"并接续;
3. **owner 体感**:跑一周,owner 的输入只剩"嗯 / go / 连走到 X",不再出现"下一步干嘛"类指令。

## 二、权威步进表(落 `master/base/docs/project/issue-pr-workflow.md`)

适用:有 Issue 的开发任务。低风险单会话小改照旧走「流程按需升级」豁免,不进闸。

| 步 | 干什么 | 完成判据 | 过闸报告(报完停,等一字放行) |
|---|---|---|---|
| 0 取活 | 指派或 `gh issue list` 挑活;读完整评论 + 验 doc 链接 | 知道"做什么 + 怎么算对" | "取 #N,计划:细化→实施→验证→交付→收口(小任务提议跳细化)。开工?" |
| 1 细化(可跳) | 端内方案 / spec,评论 announce | spec 落盘且验收可检验 | "spec 好了(链接)。下一步实施,继续?" |
| 2 实施 | 写代码;**步内自决不阻塞**;方案变更回写 issue | 代码完成 + 自验通过 | "实施完、自验过。下一步验证 + 新眼睛复审,继续?" |
| 3 验证+复审 | 跑验收命令;新眼睛 review;修 findings | 验收全过 + findings 清零或标记 | "验证/review 过(证据贴附)。下一步交付 PR,继续?" |
| 4 交付 | `$commit-msg` + PR(`Refs #N`)+ 按授权合并 | PR 合并 | "PR #M 合了。下一步收口,继续?" |
| 5 收口 | 勾完流程格、核关闭条件、收口评论、`Closes` | issue 关闭 | "#N 收口。**建议下一个:取 #M(一句理由)**。做吗?" |

- **批量放行**:owner 说"连走到 X"→ 中间闸静默通过,只在 X 报到。
- **高风险闸独立**:烧钱 / 生产 / 改历史不随步闸放行,照旧单独确认。
- 第 5 步"建议下一个"扣回第 0 步 = 跨任务续接。

## 三、双状态锚(主从定死)

- **真相源 = issue 正文的流程勾选框**(见 §四模板节):每过一闸勾一格;跨会话定位靠它。
- **会话内投影 = 任务清单**:接活第一动作把 6 步展开成任务清单逐步勾——它每轮自动出现在 agent 眼前,不吃注意力衰减。
- 两处不一致**以 issue 为准**;需求中途变更要回退步骤 → 评论说明 + 改勾,不许静默回拨(凭据保真)。

## 六、风险 / 未验证(诚实标坑)

- 「接活先展开任务清单」这个首动作本身仍是 nudge——它失守则会话内锚不生效(跨会话锚仍在);这正是排队的 Stop hook 要兜的洞。
- 确认疲劳残余风险:6 闸/任务是推测的舒适密度,实跑后 owner 觉得烦 → 调稀(如默认"连走到交付")属参数调整,不动架构。
- 步进表与多端 6+1 骨架(coordination-multiend)是两个视角(单 agent 任务级 vs 跨端协调级),本期不合并;若实跑发现 agent 混淆,再做指针互指。
- 验收 c(一周体感)依赖 owner 主观报告,无自动度量——与北极星"爽感数据点"一致,接受。
