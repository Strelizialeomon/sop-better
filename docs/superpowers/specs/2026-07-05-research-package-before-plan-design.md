# 方案前调研包设计

- **日期**:2026-07-05
- **状态**:已落地到 STANDARD / 母本 / sop-audit / exp-021
- **目标**:把“给方案前先调研真实情况”从一句质量要求,改成可检查的轻量交付物:调研结论、主流做法、建议方案、信源凭据、未验证风险。

---

## 1. 问题

旧版“方案前证据优先”方向对,但形态不够准。它强调“方案要有依据”,容易被 agent 做成:

- 方案已经写完,末尾补一句“依据:官方文档”。
- 只标“未验证 / 风险”,但没有先给主流做法对比。
- 审计时只查有没有“证据优先”字样,没法判断 agent 是否真的调研过。

用户真正想要的是:agent 像靠谱顾问一样,先查资料和主流做法,再给可决策建议。信源不用大段展示,但推荐必须有可靠来源支撑,不能凭训练记忆拍。

---

## 2. 外部依据

调研结论支持“先调研,再建议,但按任务分级”:

- [OpenAI Web Search 文档](https://developers.openai.com/api/docs/guides/tools-web-search):联网搜索适合获取最新信息并提供来源引用;复杂研究更慢,简单查询更快,说明不能把所有任务都推成深度调研。
- [Anthropic Building Effective Agents](https://www.anthropic.com/engineering/building-effective-agents):agent 的基础能力包括 retrieval / tools / memory,但复杂度、延迟、成本要权衡,应从够用的简单方案开始。
- [Anthropic Context Engineering](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents):系统提示要介于“太虚”和“硬编码 if-else”之间;本规则应写触发条件和 carve-out,不能写成死规矩。
- [Google Grounding 文档](https://docs.cloud.google.com/gemini-enterprise-agent-platform/models/grounding/overview):把输出连接到可验证数据源可以减少编造,并提供可审计来源。
- [RAG 论文](https://arxiv.org/abs/2005.11401):模型参数内知识有局限,更新世界知识和提供来源本身就是难点;检索增强能让输出更事实化。

结论:规则应叫“方案前调研包”,不是“网络调研优先”或“证据优先”。网络和官方文档只是信源的一部分;源码、实测、release note、行业主流实践也可以是强依据。

---

## 3. 调研包格式

触发任务:方案 / 设计 / 估算 / 选型 / 外部平台接入 / 重要 SOP 调整。

最小交付物:

```md
调研结论:
...

主流做法:
1. ...
2. ...
3. ...

建议方案:
...

信源凭据:
- 来源:证明什么 / 可信度

未验证 / 风险:
...
```

要求:

- **调研结论**:先说查到的真实情况,不是先抛方案。
- **主流做法**:列 2-4 种常见解法,说明各自适合什么情况。
- **建议方案**:明确推荐一个,并说明为什么。
- **信源凭据**:可以短,不用堆链接;但必须能证明 agent 真查过。优先真实环境实测 / 官方文档 / 源码 / 标准规范 / release note / changelog;博客、GitHub issue、StackOverflow 可当线索,关键结论要尽量回一手源或实测。
- **未验证 / 风险**:明确哪里没跑、哪里可能错。

## 5. 验收标准

- `STANDARD.md` 使用“方案前调研包”,不是“方案前证据优先”。
- `master/base/AGENTS.md` 明确调研包五件套。
- `$sop-audit` severity 映射含“方案前调研包”。
- spec / exp / PLAYBOOK 不再把旧口径当最终结论。
- 反向边界保留:低风险局部补丁、纯解释、稳定常识、无真实环境可摸的小事不强制调研包。

可检查场景:

1. “这个依赖怎么选?” → 先给主流做法 + 推荐 + 信源凭据。
2. “某平台 API 能不能这样接?” → 先查可靠来源,信源凭据说明证明什么。
3. “帮我改 README 一个错别字” → 不强制调研包。
4. “优化架构”但没看代码 → 先读项目结构 / 关键配置,不能直接给泛泛方案。

---

## 6. 边界

- 这条不替代 spec 新眼睛 review;它是前置调研交付物,spec review 是后置安全网。
- 这条不要求每次都写长研究报告;小方案可以用紧凑五段。
- 官方信源优先,但不迷信官方;官方过时 / 说法不完整时,源码、实测、issue 复现也可以推翻或补充。
- 如果环境无法访问网络或真实系统,agent 要明说“未联网 / 未实测”,再给保守建议。
- 如果用户明确要求“不要联网 / 只凭当前上下文”,按用户当场指令执行,但标记未验证风险。
