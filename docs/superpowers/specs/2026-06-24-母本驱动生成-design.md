# 母本驱动生成（reference-master-driven generation）· 设计

- **日期**：2026-06-24
- **状态**：设计已定，待写实施计划（本身 = exp-014 撒手实验）
- **一句话**：`/sop-init` 不再从抽象 `templates/` 碎片拼装，改成从**清洗+开槽后的具体母本**（media-ops 为基 + taoxi-geo 抠 worktree）整份 copy + 填槽 + 剪枝；`/sop-audit` 改成对母本做**机械双向 diff**。STANDARD §1 公约保持抽象权威不动。

---

## 1. 病根（为什么改）

"调了很多轮效果始终不好"的根子，是**抽象蒸馏每过一轮就丢一点真项目里的载重结构**（exp-006 元教训）。一图为证：

- `media-ops/CLAUDE.md:8` 把「起手新鲜度」摆成 **§最高优先级第一节**，自带"为什么排第一"的生产安全论证。
- 抽象模板 `templates/agent-constraints.md:15` 把同一条埋成括号里小项，标题还叫"别全塞这"。
- **同一条规则，真项目里戴皇冠、蒸馏版里进地窖。**

> ⚠️ 自检修正（round-1 新眼睛）：freshness 这例子**没当初说的那么干净**。`agent-constraints.md:15` 那个括号是 exp-006 **故意的瘦内核**（情景规则挪去 on-demand doc、留指针，不是"蒸馏丢了"——full freshness 机制在 `issue-pr-workflow.md` 里没被埋）。media-ops 摆它第一节，是因为它是**项目级 always-loaded doc（不同海拔）+ 2人 git 协同 + 读生产**，风险画像本就高。所以这条只证明"**风险高时实例化该更显眼**"（turn-1 的精确结论），**不**证明"抽象必丢载重"。

系统性证据其实在**别处**：exp-012（挂错闸）/ exp-013（删除残留盲）是真·抽象件机制 misfire；更扎心的是 **media-ops 自己至今还带 S1·C1 + 缺 exp-011 受众闸 + 缺承重墙不豁免行**——这是「**回灌没传到位**」（exp-007续），不是"抽象 vs 具体"。治法仍可指向"具体母本 + 单一实例化源 + 机械漂移逮"，但**前提得诚实**：根问题里很大一块是回灌纪律、不是表示法（→ 见 §14 scope 决策）。

## 2. 两个已锁的决策

| 决策 | 选定 | 理由 |
|---|---|---|
| 「以media-ops为纲」纲到哪层 | **只纲「结构+实例化」，公约保持抽象权威** | 反驳/凭据保真/说人话是跨项目通用、13 实验验过的承重墙地基，不是 media-ops 特有；media-ops 自己也会因项目原因漂移（现就带已废 S1·C1），不能托管通用核 |
| 母本物理放哪 | **copy 进 sop-better（清洗+开槽的整份骨架）** | `/sop-init` 不依赖目标机器有 media-ops、输出确定；防漂靠"母本↔真仓机械 diff"+回灌；清洗只做一次、新项目总拿已知好版 |

## 3. 架构（三层，公约仍是唯一权威）

```
STANDARD §1 公约(抽象权威·不动)
        │  长出新护栏就「回灌」进 ↓
   master/(具体母本·copy进sop-better)
        │  /sop-init: copy整份 + 填槽 + 剪枝 ↓
     新项目的 SOP(照真项目长出来)
```

**回灌升级**：原来"回灌"是对下游项目的苦差；现在 STANDARD §1 长一条护栏 → 回灌进 `master/` 两个来源 → 之后每次 `/sop-init` 自动继承。一处更新，全网生效。

## 4. 母本布局（三正交触发 = 三条整份层）

> ⚠️ 关键：必须保住 STANDARD §3 的**三个正交触发**，别捆成一坨（捆 = 复发 exp-012「挂错闸」：多端但串行的项目会白背 worktree 或拿不到契约）。

```
master/
  base/                     # 触发:总是(1人1端最小骨架 = media-ops 清洗 - 双角色机器)
    CLAUDE.md               # 整份带{{槽}}:起手freshness §1 → 单一真相源 → 工作约束(全carve-out) → 高风险闸 → 沟通约束 → §1.2角色变焦
    docs/decisions/         # adr-template + 0001样例 + 升级触发ADR
    docs/project/issue-pr-workflow.md   # media-ops版(决策闸carve-out等已在)
    issue模板 + label状态机(评估中/开发中/已完成 + 待业务确认)
  layer-collaborators/      # 触发:≥2个人      = media-ops 抽出的 collaboration.md(业务↔开发handoff + gh身份自动判定 + 角色命令)
  layer-multiend/           # 触发:≥2个端      = taoxi-geo 抠:docs/contracts/(README+multiend-contracts) + 每端 <end>/CLAUDE.md
  layer-parallel-agents/    # 触发:真并行多agent = taoxi-geo 抠:worktree-isolation.md + coordination.md(6+1/消息总线/scope/coordination)
  SLOTS.md                  # 槽清单 + 清洗映射(哪些是项目肉、怎么填/删)
```

> 注（自检修正）：原说"旧 `templates/collaboration.md` 一份文件两触发共用 = exp-012 隐患"——**这是错的**。实读其头部：它**早已"两段独立触发、可只有其一"**，exp-012 就是那次解耦、已 ship。所以这里把两段**物理落成两份文件**只是布局选择，**不**关闭任何 exp-012 缺口（别当卖点）。phase 4 改 STANDARD §3「一份 collaboration.md 带对应段」措辞时对齐这个物理拆分即可。

**三触发自检**（必须各归各位）：
- taoxi-geo（单人·多端·并行）= base + multiend + parallel，**不要** collaborators ✅
- media-ops（2人·单端·串行）= base + collaborators，不要后两层 ✅
- 多端串行 = base + multiend，**不**背 worktree ✅

**不变量**：每层都是**整份 doc**，`/sop-init` 只在 slot 处 find/replace，**绝不在 doc 中段动刀** → freshness 这类载重位置结构上埋不了。

## 5. 清洗规则（一条机械判据：media-ops 的东西哪些进母本）

> media-ops 每一行，问 **「STANDARD §1 背书吗？」**
> - **背书** → 留（= 公约的具体渲染：起手freshness / 缺上游不自补 / 立栈对表 / 高风险闸 / 反驳+说人话 / §1.2角色变焦）
> - **不背书** → 项目肉 → **开槽或删**：小红书/抖音、`47.109`生产IP、北极星、NOW.md、progress.yaml、gh用户名 → `{{槽}}` 或剔除
> - **已废** → 删：`S1·C1`、"两根轴"档位（exp-012/013 早杀，media-ops 自己还留 = 趁清洗修掉）

**槽清单（初版，SLOTS.md 维护）**：`{{proj}}`（项目一句话，别写档位/“单人”窄化词）、`{{ends}}`、`{{house_style}}`（指参考仓本体·无则"无参照"）、`{{risk_gate_items}}`（高风险闸条目）、`{{prod_infra_note}}`（如 VPN/IP 旁注，可空）、`{{role_identity}}`（单人=§1.2角色变焦；2人=gh身份判定，在 layer-collaborators）。

**已决**：北极星 / NOW.md / progress.yaml **剥掉**（不进通用基线）。想通用 → 先进 STANDARD §1，再流进母本。

## 6. `/sop-init` 新流程

1. 读 `STANDARD.md §1`（公约权威，不重抄）
2. 定参数（ends / collaborators / risk / house_style；能从代码推断就推断，推不了一次问清）
3. **右尺寸校验**（反驳在此发力：多端/多人结构是真有还是预建？真一次性脚本 → 建议别 init）
4. **copy `base/` 整份 → 填槽**
5. **按三触发各 copy 对应 layer 整份**（≥2人→collaborators；≥2端→multiend + 每端CLAUDE.md；并行→parallel-agents）。没触发不 copy（右尺寸硬约束）
6. **增量幂等**：已有 SOP 只补缺的那层、不砸已有（§3.5）
7. 报告 + 便宜验证（owner 扫 CLAUDE.md + 目录树即可验收）

## 7. `/sop-audit` 改成双向 diff（exp-013 根治；exp-010 只减负、不根治）

> ⚠️ 自检修正：只 `stale` 方向（项目留着 master 已删的块）是真·机械逮 = exp-013 根治。`missing` 方向（项目缺护栏）仍要 exp-010「近似≠覆盖」那套语义 LLM 读，**没机械化**。且 diff 必须 **layer-gated（只比触发命中的层，剪掉的层不算 missing）+ slot-masked（槽是洞、不参与比）**，否则填好的槽 / 正当宽放 / 正确剪掉的层全被误报。剩下区分仍是语义判，诚实标。

| 维度 | 老 baseline | 新 baseline |
|---|---|---|
| 对照物 | STANDARD 抽象正文（语义判，会漏） | **项目 doc ↔ `master/` 对应 layer 当前版**（具体↔具体） |
| 增方向 | 近似≠覆盖靠 LLM 读 | 项目缺 master 有的护栏 = `missing`（机械） |
| 删方向 | **盲**（exp-013） | 项目留 master 已删的块/档 = `stale`（机械逮，如残留 S1·C1） |
| 母本保鲜 | 无 | **一次性 bootstrap**：从 media-ops/taoxi-geo 抠出 `master/` 后，它俩**翻成 master/ 的下游消费者**——跟其它项目一样跑 `/sop-audit`（机械 diff），不需要单独的"master↔真仓"保鲜机制。它俩日后长出的护栏经**回灌**进 master/ |
| 本地偏离 | — | 正当本地偏离照旧**宽放**（右尺寸，不报；§5.1 防过度治理不破） |

> 诚实修正：早先说"母本↔真仓机械 diff"是overstate——`master/base` 是 media-ops 清洗+解构后的派生物，跟它**不是逐字一致**，那个方向的 diff 是语义的。所以不另设保鲜机制：bootstrap 后 media-ops/taoxi-geo 当下游项目审（机械），唯一真·语义边界只剩 §1↔master/（见 §10），靠保真清单 + 回灌兜。

audit 头号仍是"过度治理"，其余维度（结构错配/沟通约束塌口号/结构缺失/凭据失真）保留；只是"漂移检查"从语义升级成机械双向 diff。

## 8. 🧱 承重墙保真清单（exp-006 雷区 · make-or-break · 强制 + 新眼睛）

搬迁/蒸馏最容易在"摘要版"丢安全网。实施第 1 步**必须**：

- 建映射表：**STANDARD §1 每条 + 每个 exp-NNN carve-out**（004缺上游 / 007决策闸 / 008立栈 / 009 escalate / 011说人话闸 / 012挂对闸 / 013双向diff）→ 兑现在 `master/` 哪个文件哪行。
- 派**独立新眼睛子代理逐条撞**（exp-006：减法/搬迁比加法更要新眼睛）。
- **双向反向验收**（exp-005/006）：① master 没丢任何护栏；② 搬迁没偷加新 covenant（**STANDARD §1 净变 ≈ 0**，这是硬指标）。

## 9. 范围 / 非目标（期望校准）

- **杀**：生成/审计机制 misfire 类——freshness 被埋、exp-010 近似漏报、exp-012 挂错闸、exp-013 删除残留。
- **不杀**：新领域 carve-out 照样会冒（exp-004/007/008/009/011 那种真学习）——但回灌让传播变便宜。
- **不碰**：STANDARD §1 公约内容（只换它的实例化来源）。

## 10. 风险与缓解

| 风险 | 缓解 |
|---|---|
| §1 抽象 ↔ 母本具体 = 两份公约，违 §1.6"重抄必漂移" | 二者不同海拔（原则 vs 实施条例），非纯复制；边界 diff 是**语义非机械**（exp-010 弱区），靠"保真清单 + 回灌纪律"兜，不假装机械可逮 |
| 母本（快照）本身再漂 | 母本↔真 media-ops/taoxi-geo 机械 diff 进 audit；回灌时一并更新 |
| 搬迁丢护栏 | 第 8 节保真清单（强制 + 新眼睛 + 双向验收） |
| 把 media-ops 项目肉/已废档带进新项目 | 第 5 节清洗规则（§1 背书判据）+ audit `stale` 逮残留 |
| 大改动 = 高 stakes | 分支上做、回 main；分期落地；每期可独立验；dogfood 复验 |
