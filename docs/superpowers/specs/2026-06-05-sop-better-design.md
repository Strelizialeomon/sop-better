# sop-better 设计 spec

- **日期**:2026-06-05
- **状态**:已与 owner 对齐(对话中拍板"开干")
- **本 spec 由来**:这份设计本身是一次 L2 撒手实验(见 `experiments/2026-06-05-001-design-sop-better.md`)——AI 扛设计,owner 评审拍板。

---

## 1. 这是什么

一个**私人撒手训练场 + 活的操作手册**。owner 在真实任务上,一次次把"认知决策"往 AI 手里多交一点,记录爽感与翻车,把"什么能安全交出去"沉淀成 `PLAYBOOK.md`。

**v1 零代码**。产物 = 一个结构化日记本(README + PLAYBOOK + 实验记录)。

它**不是**:代码规范整理工具、多端项目脚手架、给别的项目做治理的系统。

## 2. 为什么(诊断)

**表层痛点**:owner 用 AI 后没有爽感、没有飞跃性效率提升,"还是在做开发,只是不直接写代码"。

**挖出的根因**(来自对 issue #126/#127 实际驱动方式的分析):

- owner 在这些 issue 里**做了全部认知决策**:数据模型、算法(覆盖法排名/滞后窗口/质心向量)、包结构、Asynq vs outbox 取舍、连阈值都拍好;AI 只是实现 + 抓 bug。
- 即:**难的 80%(思考)留给自己,只把打字的 20% 交给 AI**。累的部分没卸,所以"还是在做开发"。
- owner 自陈:**从没试过**把"设计/取舍"交出去,习惯性自己上,潜意识有一点没审视过的不信任。

**更深一层**:owner 现有 SOP(细粒度、详 spec、跨端契约、逐 task review、audit 补口)——**全是控制机制**,为"正确 + 可审计 + 多 agent 协作"优化,不为"杠杆 + 爽感"优化。爽感在相反那条线(*AI 做了我没想到的、且不错*),被流程工程掉了。

**机制钥匙**:不敢撒手的根子不是"不信任 AI",是"**验证太贵**"——无法便宜检查 AI 的设计好坏,只能提前控死。

```
要爽感  → 撒手交认知    要敢撒手 → 验证便宜 + 爆炸半径有界
```

## 3. 撒手梯子(L0–L4)

把"粒度"变成能拨的刻度盘。每次实验明确站哪一格:

| 档 | 交出 | 保留 |
|---|---|---|
| L0 | 只交打字 | 设计/取舍全自己做(← owner 当前默认,#126/#127 在此) |
| L1 | 细节决策 | 给方案骨架,AI 填肉 |
| L2 | 整个方案 | 只给 目标+约束+验收,AI 设计,owner 拍板 |
| L3 | 什么算做完 | 只给目标,AI 拆解+设计+定义完成,owner 抽检 |
| L4 | 做什么 | 给模糊愿景,AI 提议做啥、自己框范围 |

每次实验 = 从默认档**往上挪一格**。

## 4. 实验闭环(5 步)

一次实验 = 一份 `experiments/YYYY-MM-DD-NNN-名字.md`:

1. 选活 + 定档(真实任务,高一格)
2. **便宜验证方案**(动手前硬门槛):"怎么在 X 分钟内、不逐行读看出对错?" 答不上 → 先补功课
3. 下简报:只给 `目标 + 约束 + 验收`,不给解法
4. AI 跑,owner 评分(设计质量 / 省力 / **爽感** / 验证成本)
5. 抽一条教训 → 回填 `PLAYBOOK.md`

## 5. PLAYBOOK(活手册)

实验的结晶。每条**必须有实验编号背书**,禁止凭感觉写。这是 owner 最初想要的"固化好 SOP",但固化的是证据换来的新打法。

## 6. 仓库结构

```
sop-better/
├── README.md
├── PLAYBOOK.md
├── experiments/{_TEMPLATE.md, YYYY-MM-DD-NNN-*.md}
└── docs/superpowers/specs/2026-06-05-sop-better-design.md
```

沿用 owner 既有习惯(`docs/superpowers/specs`、实验编号),降低上手摩擦。

## 7. 范围外(YAGNI)

- 不写工具/CLI/自动化(没数据前是想象)
- 不搬多 agent 契约/coordination/audit 仪式(那是控制机器,本项目反其道)
- 不顺手治理别的项目

**安全待办**(挂名,另开):`py-script` / `jiandaoyun_cralwer` / `vpn-tutorial/CREDENTIALS.md` / `llm_auto_report` 的硬编码密钥——真实风险,与本项目无关。

## 8. 成功标准

跑 5~8 次后:有几次真实"卧槽行"瞬间;`PLAYBOOK.md` 攒出 owner 自己的"什么活到哪档";默认档上移 ≥1 格;省力/爽感评分趋势向上。

## 9. 流程注(本项目原则的第一天演示)

本项目**故意不跑** writing-plans → subagent-driven 等重型实施流程。理由:产物是 5 个 markdown,给它套四道流程闸与本项目"反对无谓仪式、右尺寸流程"的论点自相矛盾。**右尺寸流程也是纪律**——这是项目原则在 day-1 的现身说法。后续若长出真代码,再按需引入相应流程。
